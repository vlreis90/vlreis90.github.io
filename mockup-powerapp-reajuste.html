Blueprint de Implementação

Como construir, na prática.

Cada peça da arquitetura, com sua receita básica.

1 SharePoint List · Estrutura

Crie uma lista ReajusteContratual com as colunas:

  • GrupoCliente — Texto
  • NomeCliente — Texto
  • Diretor — Pessoa (ou Choice)
  • Gerente — Pessoa (ou Texto)
  • StatusReajuste — Choice (Em negociação / Aguardando aprovação / Aprovado / Carta enviada / Cobrança ativa / Concluído)
  • Observacao — Texto multilinhas
  • DataInicio — Data
  • DataEnvioCarta — Data
  • DataInicioCobranca — Data
  • FollowUp — Data
  • RetroativoDataInicio — Sim/Não
  • UltimaAtualizacao — Data e hora (auto)
  • AtualizadoPor — Pessoa (auto)

2 Power Apps · Telas

Canvas App com 4 telas: scrHome, scrClients, scrColumns, scrEdit.

Galeria de diretores (scrHome):

Distinct(ReajusteContratual, Diretor.DisplayName)

Galeria de clientes (scrClients):

Filter(
  ReajusteContratual,
  Diretor.DisplayName = varDiretor
)

Salvar nova atualização (scrEdit, botão Salvar):

Patch(
  ReajusteContratual,
  varClienteSelecionado,
  { StatusReajuste: drpNovoValor.Selected.Value,
    UltimaAtualizacao: Now(),
    AtualizadoPor: User() }
);
Navigate(scrColumns, ScreenTransition.Fade)

3 Power Automate · Notificação

Fluxo agendado Recorrência: toda segunda às 9h.

  • Get items da lista ReajusteContratual
  • Group by Diretor (variável de array)
  • Apply to each diretor → Send email (V2) personalizado com a contagem de pendentes daquele diretor + link do app
  • Opcional: integração com Teams (Post message in chat) em vez de e-mail

Link direto do app filtrado: use Param("diretor") no OnStart e passe ?diretor=Carlos%20Mendes na URL.

4 Power BI · Provisão de valor por etapa

O dashboard cruza duas fontes e expõe quanto valor financeiro está provisionado em cada estágio do funil de reajuste — transformando o acompanhamento de status em uma visão de impacto financeiro real.

Fontes integradas:

  • SharePoint List — estado operacional do reajuste (status, datas, diretor responsável)
  • Banco Financeiro — valores contratuais, faturamento atual, base de cálculo do reajuste

Modelagem (Star Schema):

// Tabela fato: cruza operacional + financeiro
fato_Reajuste =
  NATURALINNERJOIN(
    SharePoint_Reajuste,
    Financeiro_Contratos
  )
// Chave de relacionamento: NomeCliente + GrupoCliente

Métricas DAX-chave:

ProvisaoEmNegociacao =
  CALCULATE(
    SUM(fato_Reajuste[ValorReajuste]),
    fato_Reajuste[StatusReajuste] = "Em negociação"
  )

ImpactoMensalAcumulado =
  CALCULATE(
    SUMX(fato_Reajuste,
      [ValorReajuste] * DATEDIFF([DataInicio], TODAY(), MONTH)
    ),
    fato_Reajuste[StatusReajuste] <> "Concluído"
  )

Visualizações sugeridas:

  • Funil financeiro — R$ provisionado em cada etapa (Em negociação → Aguardando aprov. → Carta enviada → Cobrança → Concluído)
  • Cards de KPI — Provisão total · Valor já em cobrança · Valor parado > 30 dias · Impacto mensal acumulado
  • Ranking por diretor — quem tem mais valor preso em cada etapa
  • Aging financeiro — distribuição dos valores por tempo no estágio (gargalo financeiro)
  • Gap entre Data Início e Início Cobrança — perda mensal acumulada por atraso

Resultado: cada vez que um diretor atualiza um status no app, o dashboard recalcula quanto valor saiu de uma etapa para outra — dando ao financeiro previsibilidade real sobre quando aquele reajuste vira receita.
